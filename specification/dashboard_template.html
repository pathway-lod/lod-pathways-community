Ontology term status

Which ontology terms can express what each use case needs, and which decisions are still open. Generated from ontology_terms.csv; the written specification is in SPECIFICATION.md. Discussion happens in GitHub issues: select a requirement ID to open a discussion, suggest a term or see who has taken it on.

IDUse caseRequirementStatusDecisionOwnerActionDiscussion

Status: covered = a primary term fits exactly; partial = only stand-ins or partial fits; gap = no term, or only our own local term. Decision: open = to discuss; proposed = suggested; agreed; rejected. Owner: the person named in the table, plus the GitHub users assigned to the issue (shown with @). The filters are kept in the address, so a filtered view can be shared as a link.

Edit ontology_terms.csv, then run python check_terms.py --update --render to refresh this page and the tables in SPECIFICATION.md.
