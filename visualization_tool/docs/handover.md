For whoever (person or coding agent) continues the viewer after ELIXIR BioHackathon Europe 2026. State as of

## Start here

1. Read [../CLAUDE.md](../CLAUDE.md) (rules, how to check changes), then [architecture.md](architecture.md). Read
   [layout.md](layout.md), [validation.md](validation.md) or [pmw-structure.md](pmw-structure.md) before touching
   the matching code, and [decisions.md](decisions.md) before changing anything a decision covers. When terms
   change (ontology terms replace `lodp:` placeholders, new scores), edit the profile and the score CSV, not the
   code: [profile-and-scores.md](profile-and-scores.md).
2. Set up: Node ≥ 22 (`npm install`; Node 20 builds the site but cannot run `tools/validate.mjs`), Edge or Chrome for
   `npm run shot`, Python with `pip install -r tools/requirements.txt` only for rebuilding data bundles.
3. Check that it works: `npm run shot -- shots/ "data=slide25.nq"`, then the global-view queries in CLAUDE.md, and
   look at the PNGs.

## Problems in the data, found while building the viewer

These are for the RDF and term-table maintainers, not for the viewer (decision 2026-11-11: the viewer shows what the
data says). Not reported to the team as of 2026-11-13.

- **PlantMetWiki renumbered its pathways after the 2026-10-01 snapshot.** 0 of 1,162 `PC<n>` numbers in the pilots'
  snapshot table (`../pilots/pairedomics_overlap/data/plantmetwiki_pc_pathways.csv`) still point to the same PlantCyc
  pathway; every pathway anchor of the association, bgc and plantcyc pilots (50 + 267 + 171 distinct) now resolves to
  a different pathway. All of them can be remapped through the PWY id (old PC → PWY → today's pathway), which is what
  the snapshot's `alias` table does (`tools/build_pmw_snapshot.py --old-pc ...`). `shape_constraints/build_rdf.py`
  builds its anchors from that same table, so the mapping matches how the RDF was made. Following `pav:hasVersion`
  instead would silently place claims in wrong pathways. The release string (`r17.0.0_20260605-171052`) did not
  change with the renumbering, so it cannot detect it.
- PlantCyc pilot: subject IRIs of diagram nodes carry old PC numbers and have no triples in live PlantMetWiki.
- Association pilot: claims are anchored to several pathways at once (median 2, max 31; "union of pathways"). This
  joins most association claims into one network (1,183 of 1,293).
- `lodp:identificationTier`, `lodp:precursorMzDifference`, `lodp:libraryCompoundName` are in `lodp.ttl` and the RDF
  but not in `specification/ontology_terms.csv` (shown as "not in spec").
- `lodp:run_gnps_library` has no version (SHACL warning on ~140 annotation claims, because the run is shared).

## Known issues

- **SVG export shows "weird characters" on a Mac** (reported by a colleague, not reproduced, not fixed). The export
  is HTML in SVG (`foreignObject`, html-to-image), UTF-8 without XML declaration, no embedded fonts, fixed pixel
  boxes. Candidate causes, most likely first: (1) other fonts in fixed boxes, so text wraps and overlaps (shown to
  happen in another renderer); (2) the file read as MacRoman/Windows-1252 (`·` → `¬∑`, `→` → `‚Üí`); (3) missing glyphs
  for `→ ✕ ◇`; (4) macOS `._file.svg` / `__MACOSX` sidecar files; (5) Safari saving a Web Archive. Fix candidates:
  add `<?xml version="1.0" encoding="UTF-8"?>`, embed or pin fonts, or a native SVG export (above).
- `global.html?focus=<IRI>` with an IRI that is not a claim of the file opens an empty side panel without a message.
- No automated tests. `tools/screenshot.mjs` cannot click, so the global view → card viewer hand-off (IndexedDB)
  is checked by hand: pick something on the map, "Open these n claims in detail view →", page through, "← Global view".
- More limits: architecture.md "Open work".
