# Evidence graph viewer: guide for agents

If you are taking over the viewer, start with [docs/handover.md](docs/handover.md) (current state, what waits for
review, parked ideas, known issues). Read this file first, then [docs/architecture.md](docs/architecture.md). Read [docs/layout.md](docs/layout.md)
before touching `src/layout.js`, and [docs/decisions.md](docs/decisions.md) before changing anything that a
decision there covers (most of the look and behaviour was decided by Martin Engst, who built the viewer).
Before touching `src/validation/` or `src/ValidationControl.jsx` (SHACL validation in the browser), read
[docs/validation.md](docs/validation.md): shacl-engine is pinned and patched, and results must stay identical to pyshacl.
Before working on the PlantMetWiki part of the global view, read [docs/pmw-structure.md](docs/pmw-structure.md)
(what PlantMetWiki contains, numbers, clustering options, queries).

This folder is part of [pathway-lod/lod-pathways-community](https://github.com/pathway-lod/lod-pathways-community);
the repository's own README and conventions apply too.

## What this is

A browser viewer for **evidence RDF** of the LOD-pathways / PlantMetWiki evidence model (ELIXIR BioHackathon Europe
2026, project 3, "Developing Open Standards for a Semantic Framework in Plant Specialized Metabolism"). A *claim*
(prediction or result) points to *evidence* nodes (typed with ECO classes), each generated by a *run* (tool,
version, input; PROV), and is *anchored* to an existing PlantMetWiki node (pathway, metabolite). The viewer shows a
subset of such RDF as cards in columns by role, with term status from the project's term table and problems from
SHACL validation. Target audience: data submitters (what did I upload, which terms are agreed, what is missing);
it should work for any RDF that fits the model.

What the viewer uses from the rest of this repository (read-only; only for rebuilding the data bundles):
- `specification/ontology_terms.csv`: the term table (source of truth for terms).
- `shape_constraints/shapes/*.ttl`, `shape_constraints/vocab/lodp.ttl`: SHACL shapes and the `lodp:` vocabulary.
- `shape_constraints/rdf/annotation.ttl`, `examples/sample_evidence_graph.ttl`: the RDF of the two examples.

Related:
- [pathway-lod/developing-open-standards](https://github.com/pathway-lod/developing-open-standards): the paper.
- PlantMetWiki SPARQL endpoint: <https://plantmetwiki.bioinformatics.nl/sparql> (the viewer itself never queries it live; `tools/build_pmw_snapshot.py` builds the snapshot for the global view's map from it).

## Run, build, check

```bash
npm install
npm run dev                                   # http://localhost:5173  (?data=...&focus=... see README)
npm run build                                 # static site in dist/
npm run shot -- out.png "data=slide25.nq"     # build + headless screenshot (tools/screenshot.mjs)
```

**There are no automated tests.** Every change is checked visually: build, take screenshots with
`tools/screenshot.mjs`, and look at them (an agent can read PNGs). After any layout or rendering change, check at least:

| Query | Why |
|---|---|
| `data=slide25.nq` | the reference picture (slide 25 of the 2026-11-03 community call); must stay readable |
| `data=slide25.nq&layout=slide` | the slide-like column order must keep working |
| `data=sample_evidence_graph.nq` | all four use cases (BGC, paired omics, metabolomics, PlantCyc), claim-to-claim links, KG groups |
| `data=sample_evidence_graph.nq&runs=1&focus=https://example.org/lod-pathways/pilot/annotation_MTBLS14270_pos_741` | runs as cards, a claim with four evidence/data edges |
| `data=sample_evidence_graph.nq&profile=` | no profile: the generic fallback must still work |

After any change to the global view (`global.html`, `src/Global.jsx`, `src/globalLayout.js`, `src/kg*.js`,
`src/siblings.js`, `src/scores.js`), check with `npm run shot -- shots/ --page global.html "<query>" ...`:

| Query (`--page global.html`) | Why |
|---|---|
| `data=all_pilots.ttl` | the default page: PlantMetWiki map with all 4,884 pilot claims, blocks, ribbons |
| `data=all_pilots.ttl&focus=https://example.org/lod-pathways/pilot/annotation_MTBLS14270_pos_741_GMMLNKINDDUDCF` | claim panel: cards with a PlantMetWiki stub (D37) and the "Shares with other claims" bar |
| `data=all_pilots.ttl&pick=node:https://identifiers.org/inchikey/CJXMVKYNVIGQBS-OWOJBTEDSA-N` | a shared-node pick: 22 claims listed and shown as a grid of cards in the panel (D38) |
| `data=all_pilots.ttl&score=lodp:dreamsSimilarity&top=50` | Score panel: histogram, top 50, blue dots on the map (D36) |
| `data=sample_evidence_graph.nq&layout=ring` | the older anchor ring, URL only (D39) |

A `focus=` IRI that is not a claim of the file gives an empty panel, so copy IRIs from the file. The hand-off between
the two pages (IndexedDB) needs clicks, which screenshot.mjs cannot do: check it by hand (docs/handover.md, "Known issues").

`npm run shot -- shots/ "<query1>" "<query2>" ...` writes one PNG per query into `shots/` (git-ignored).

The Data menu (`public/data/datasets.json`, shared by both pages) has all four pilots as plain Turtle (`all_pilots.ttl`,
made by `tools/rebuild_bundles.sh`, no SHACL report; the default of both pages) and the sample graph (D32, D41).
`slide25.nq` is no longer in the menu but stays in `public/data/` for the checks above (`data=slide25.nq`). Big files
(more than 60 subjects) open on their first claim; `data=all_pilots.ttl` is the big-file test. Other files: bundle
locally (example at the end of `tools/rebuild_bundles.sh`) and open them with "Open Turtle file"; do not add them to
`public/data/` without a decision.

After changing `src/validation/`, the shapes or the validator's dependencies, compare `node tools/validate.mjs <file>`
(Node ≥ 22) with `python ../shape_constraints/validate.py <file> --no-references` (docs/validation.md, "How to check").

Rebuild the data bundles (only when the sample graph, shapes, term table or `data/slide25/*.ttl` change):
`bash tools/rebuild_bundles.sh` (reads the repository root `..`; needs `pip install -r tools/requirements.txt`).

## Rules for changes

1. **The core knows no vocabulary.** `src/rdf.js`, `src/model.js`, `src/layout.js` and the React components must
   not contain evidence terms (`lodp:`, SIO, ECO, PROV, WikiPathways IRIs, tier names, slide-specific strings).
   Anything vocabulary-specific goes into the profile (`public/profiles/*.json`), read by `src/profile.js`;
   how to edit it and the score CSV: [docs/profile-and-scores.md](docs/profile-and-scores.md).
   Reason: the ontologies are not decided yet; when they are, only the profile (and the vocabulary in the bundles)
   should change. See decision D8.
2. **Layout is deterministic.** Same input, same picture. No force layout, no randomness. See docs/layout.md.
3. **Keep both layouts working** (`compact`, the default, and `slide`), and the no-profile fallback.
4. **Card width is fixed** at 400 px in two places that must match: `.card { width }` in `src/styles.css` and
   `COL_W` in `src/layout.js`. The edge-label font is defined in three places that must match: `.edge-label` in
   `src/styles.css`, `labelStyle` in `src/App.jsx`, and `measureCtx.font` in `src/App.jsx` (used to size the gaps).
5. **Every option that changes the picture must be part of `viewKey`** in `src/App.jsx`. The ReactFlow provider is
   keyed by it; a new key remounts the graph, which re-measures the cards and re-runs the layout (two-pass layout,
   see docs/architecture.md). An option missing from `viewKey` will not re-layout.
6. Data bundles are **N-Quads**, not TriG or Turtle, because the SHACL report refers to blank nodes of the data and
   only N-Quads keeps their labels identical across graphs. Named graphs `urn:lodviz:<origin>` carry the origin.
7. Do not edit `public/data/*.nq` by hand; rebuild them. `data/slide25/proposal.ttl` and `plantmetwiki.ttl` are
   hand-made / fetched inputs and may be edited (keep their header comments current).
8. Keep this file, the README and docs/ current when behaviour changes; add a dated entry to docs/decisions.md for
   any change of direction, with the reason.

## Git

- This is the shared team repository: work on a branch and propose changes by pull request; commit or push only
  when the person you work for asks. End commit messages with the co-author line your harness asks for.
- The viewer is published with GitHub Pages at <https://pathway-lod.github.io/lod-pathways-community/visualization_tool/>
  by `.github/workflows/specification-pages.yml` (build with `npm ci && npm run build`, copy `dist/` into the site),
  on every push to `main` that changes `visualization_tool/**` or `specification/**`. Branches are not deployed.
- `visualization_tool/.gitattributes` forces LF line endings; `node_modules/`, `dist/`, `shots/` are ignored
  (`visualization_tool/.gitignore`).
- License: MIT, as the rest of the repository (`../LICENSE`). `data/slide25/plantmetwiki.ttl` is PlantMetWiki RDF.
- History before the move (2026-11-10, commits `0f6a54c`, `7a05435`) is in Martin's private prototype repository.
